## Glossary

> This document reuses IDs defined elsewhere rather than minting its own. This table explains those terms and how the weights below are computed.

| Term | Meaning |
|------|---------|
| NFR-XXX | Non-Functional Requirement, defined in the NFR Register. Each one is one scenario in §2 below |
| FR-XXX | Functional Requirement, defined in FRS-001 v1.1. Cited here only to measure how many an NFR affects (its Impact) |
| Priority | The NFR's Critical, High or Medium rating in the NFR Register. It sets the criticality multiplier: Critical = 3, High = 2, Medium = 1 |
| Impact | The number of distinct FR-XXX an NFR cites in the NFR Register's traceability table. If none are cited, Impact is floored at 1 |
| Scenario Score | Impact × criticality multiplier for one NFR |
| Attribute Weight | The percentage of overall importance assigned to a quality-attribute category (§1): the sum of its Scenario Scores over the total of all Scenario Scores |
| Scenario Weight | The percentage weight of one NFR relative to the others in its own category (§2) |

- Impact is the number of distinct FRs in the "Related FR (FRS-001 v1.1)" column of the NFR Register's traceability table. Three NFRs cite no FR (NFR-PERF-004, NFR-AVAIL-002, NFR-COMPAT-003) and are floored at Impact = 1.
- Attribute Weights round to exactly 100%, so no residual was applied.
- Rounding residuals on Scenario Weights were applied to the largest item in the category: Security (NFR-SEC-003), +1; Usability (NFR-USE-001), +1; Performance (NFR-PERF-002), −1; Compatibility (NFR-COMPAT-001), +1; Maintainability (NFR-MAINT-003), +1.

### Reading the Weights

The method weights each NFR by how many FRs it touches, which favors NFRs that apply to the five web app views (FR-WEB-001 to FR-WEB-005). Two effects follow, and the architect should keep them in mind when scoring alternatives:

- **Performance.** NFR-PERF-002 (view responsiveness, Medium) outweighs NFR-PERF-001 (5-minute package turnaround, Critical, AC5 Must) inside Performance, because it touches five FRs and NFR-PERF-001 touches one. NFR-PERF-001 remains the only confirmed, Must-level performance target.
- **Usability and Compatibility** rise, and **Maintainability** falls, for the same reason. Maintainability still matters for reuse, which is 15% of the hackathon evaluation.

The method is applied as defined. No weight was adjusted by hand.
