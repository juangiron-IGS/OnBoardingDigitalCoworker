## Glossary

> This table explains the ID prefixes and shorthand this document uses, so a first-time reader does not need prior knowledge of them.

| Term | Meaning |
|------|---------|
| BLG | Prioritized Backlog, this document's own ID prefix (e.g. BLG-001) |
| US-XXX | User Story, an entry in §1 (Must Have), §2 (Should Have) or §3 (Could Have) |
| AC-XXX | Acceptance Criteria scenario, a row in a story's Given-When-Then table |
| W-XXX | Won't v1 item, an entry in §4, explicitly excluded from this release |
| MoSCoW | Prioritization scheme (Must, Should, Could Have, Won't Have) this backlog uses to group stories |
| FR-XXX | Functional Requirement, defined in the Functional Requirements Specification. Every story traces to at least one (see §6) |
| UR-XXX | User Role, defined in the Functional Requirements Specification and used in each story's "As a ___" |
| BR-XXX | Business Rule, defined in the Functional Requirements Specification and referenced on the stories it affects |
| UC-XXX | Use Case, defined in the Functional Requirements Specification. A use case with no backing FR-XXX becomes a Should Have story (US-026, US-027) |
| Package line label | The label on each data point of the package: source, inferred, recommended or exception |
| Single writer | Only the JobDiva and Workflow agent writes to systems; every other agent only reads or proposes |

| Simulated system | A stand-in for JobDiva, IT, equipment, payroll or email used in the hackathon, so no real system is changed |

## 1. Must Have — Sprint 1-2

### US-001: Start a case from the JobDiva start email

**As a** recruiter or hiring manager (UR-001), **I want to** have a case created automatically from the JobDiva start email, **So that** I do not have to re-enter the new hire's start data.

**Source Requirements:** FR-ITK-001, FR-ITK-003

**Acceptance Criteria:**

| # | Scenario | Given | When | Then |
|---|----------|-------|------|------|
| AC-001 | Standard start email | A JobDiva start email arrives in the onboarding mailbox | The system processes it | A case is created containing the start data found in the email |
| AC-002 | Negative: ambiguous value | A recruiter email does not follow a standard format and a value cannot be read with certainty | The system processes it | The system asks the sender to confirm that value and does not record it as confirmed until the sender answers |

**Business Rules:** None
**Dependencies:** None
**Sprint Assignment:** Sprint 1

### US-003: Ask adaptive questions and keep one work arrangement answer

**As a** recruiter or hiring manager (UR-001), **I want to** be asked only for what is missing or unclear, **So that** I answer each question once and the work arrangement is no longer contradictory across three places.

**Source Requirements:** FR-ADQ-001, FR-ADQ-002

**Acceptance Criteria:**

| # | Scenario | Given | When | Then |
|---|----------|-------|------|------|
| AC-001 | Only missing information is asked | A case where some mandatory data is already provided and confirmed | The system asks questions | It does not ask again for any value already provided and confirmed, and each next question adapts to the answers given |
| AC-002 | Single work arrangement | The work arrangement appears with different values in different sources | The system asks | It records the single answer confirmed by the recruiter and uses it everywhere in the case |
| AC-003 | Negative: no repeated question | The work arrangement has been confirmed | The question flow continues | The system does not ask for the work arrangement again |

**Business Rules:** BR-005
**Dependencies:** US-001, US-002
**Sprint Assignment:** Sprint 1

### US-004: Check completeness of the 7 recruiter-note fields and mandatory data

**As a** member of the Onboarding Team (UR-002), **I want to** have every case checked for the 7 recruiter-note fields and all mandatory data, **So that** gaps are found before the case reaches us.

**Source Requirements:** FR-VAL-001, FR-VAL-002

- **Recruiter-note fields (FRS §3.3):** work city and state, FLSA, billing contact, timesheet approver, equipment (hardware tier and provider), sponsorship and visa (all required), and additional notes (optional).
- **Mandatory JobDiva and chat data:** role, manager, start date, client, division, line of business, employment type and vendor company, work arrangement, and pay and bill rates.

**Acceptance Criteria:**

| # | Scenario | Given | When | Then |
|---|----------|-------|------|------|
| AC-001 | Negative: blank start notes | A case whose JobDiva start notes are blank | The check runs | The 6 required recruiter-note fields are reported as missing by name, and additional notes is not reported |
| AC-002 | Negative: one mandatory data point absent | A case with one mandatory data point absent (for example the manager or the bill rate) | The check runs | The case moves to Needs clarification and lists that data point |
| AC-003 | Complete case | A case with the 6 required fields and all mandatory data present | The check runs | The case is not marked incomplete and nothing is reported as missing |

**Business Rules:** None
**Dependencies:** US-001, US-002
**Sprint Assignment:** Sprint 1
